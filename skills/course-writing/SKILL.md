# Course Writing

用于编写、重写或审查 `course/**/*.md`。规则真源是 [docs/learning-guide.md](../../docs/learning-guide.md)；本 Skill 只维护执行流程、迁移闸门和可操作自检。

## 写前

1. 阅读 `docs/strategy.md`、`docs/learning-guide.md`、学习路径和知识地图中的相关部分。
2. 涉及产品职责时读取 `SPEC.md`、`PLAN.md` 和对应项目篇。
3. 涉及已有实现时读取配套正文、实验代码、README 和真实测试。
4. 判断文档属于概念、机制、实验还是项目；不能同时承担多个主体。
5. 用一句话写下核心问题、学习者已有输入、本文交付和非目标。
6. 判断知识是学习主线、扩展还是未来认知，以及产品是必接、条件接入、受控实验还是不实现。
7. 先确定解释顺序和主要数据或状态流，再决定标题，不套固定目录。
8. 涉及 MCP、A2A、Agent Skills 等演进协议时，核对官方当前稳定规范，记录正文依据的规范修订和实验使用的 SDK 版本，区分稳定核心、可选扩展、实验能力与已弃用内容。
9. 涉及 Agent 框架时，先标明 Provider API、框架运行时、本地通用封装和产品领域组装分别负责什么，并判断当前内容是在解释稳定机制还是某个版本的 SDK 用法。

## 学习者路线

优先使用下面的解释顺序：

```text
当前遇到的具体问题
→ 已有经验能建立的直觉
→ 数据或状态推进时需要的新术语
→ 主要机制和关键约束
→ 正常边界与失败边界
→ 在需求评审助手中的位置
→ 实验观察与修改验证
```

新术语第一次出现时先用自然语言解释。不要在开头罗列完整架构，也不要用尚未解释的术语互相定义。

## 粒度闸门

一篇正文只回答一个核心问题。若出现两个独立生命周期、两种主要状态变化、两套实验变量或不同失败模型，优先拆分。

协议课程尤其要分开：概念与责任边界、能力模型、协议生命周期、真实接入实验、项目职责和验收。工具课程还要区分“是否应当使用”与“运行时怎样执行”。一节课可以链接机制篇和实验篇，不因文件数量增加课程序号。

学习路径中的每个编号必须有当前问题和学习交付，不能只写标题、状态或实验链接。知识地图中的每个节点必须有核心问题与边界说明。

## 概念篇

至少讲清：

- 学习者当前为什么需要这个概念。
- 用自然语言表达的定义和最小心智模型。
- 输入、输出或主要参与者。
- 与相近概念的区别。
- 一个误区或反例。
- 适用和不适用边界。
- 在产品中的位置，但不展开项目实施。

默认不讲实现代码、运行命令和项目任务。阶段完成后可以补充“学完后回看”，但不能变成全部机制的汇总。

## 机制篇

至少讲清：

- 当前问题和已有输入。
- 一条主要数据流、状态流、证据流或异常流。
- 新对象为什么在此时出现。
- 一个关键约束或不变量。
- 简单方案为什么不足。
- 正常边界和失败边界。
- 本文向后续能力交付什么。

机制篇可以使用公式、状态图、业务样例和最小抽象数据形状；不系统讲源代码、SQL、Shell、文件树、公共类调用、完整日志字段、安装步骤或读码顺序。只有缺少某段关键语法就无法解释机制时，才保留极少量片段并立即回到原理。配套实验只链接，不复制操作手册。

机制篇中出现具体文件、类、函数或配置路径时，逐项判断它是否真的不可替代；能够用抽象责任表达的，迁入实验篇。

## 实验篇

正文位于 `course/labs/`，代码位于 `source/demos/` 或产品。实验篇必须让学习者不依赖已删除的旧文档也能完成操作。

至少讲清：

1. 对应机制、观察问题和不能证明的内容。
2. 环境、真实依赖、凭证、数据和运行前检查。
3. 唯一主入口、精确命令、参数、默认值和退出状态。
4. 固定输入、运行前预测和唯一主要变量。
5. 正常输出、关键日志字段和读法。
6. 自然边界、真实依赖失败和确定性失败的区别。
7. 按“表现 → 可能层次 → 验证方式”组织的排查顺序。
8. demo → 公共入口 → 核心步骤 → 测试的读码路径，并说明各自责任。
9. 一个修改任务、预期变化、不应变化的契约和验证命令。

Mock 必须标明验证对象和局限，主路径仍指向真实服务。存在稳定失败复现时，要明确它证明状态机或错误契约，不证明真实服务质量。

## 项目篇

项目篇引用 `SPEC.md`，不复制产品规格或产品 README。至少讲清：

- 阶段学习目标和核心业务问题。
- 已有能力和 Definition of Ready。
- 数据、状态、工具、证据和异常怎样流动。
- 必须做出的设计选择。
- 真实代码入口和组合责任。
- 集成检查点及其验收证据。
- 自然 bad case、需求变更和回归。
- 明确不做的能力。

## 重构迁移闸门

课程精简或职责迁移时，删除原内容前必须完成：

1. 枚举准备删除的代码、命令、输出解读、调试、读码和验收内容。
2. 将每块内容标记为机制、实验、README、测试、SPEC / PLAN / 项目篇或废弃。
3. 先在目标位置形成可用内容，再删除原文。
4. 检查代码注释、README、学习路径和相邻课程是否仍引用旧位置。
5. 验证命令、参数、默认值、文件路径和测试入口与当前代码一致。
6. 删除临时迁移清单，不把迁移过程写入长期文档。

不能因为实验篇出现了“预测、日志、测试”等关键词就判断迁移完成。必须实际检查学习者能否准备、运行、观察、定位、修改和验证。

## 实验与验收纪律

- 先预测再运行，一次只改变一个主要变量。
- 复用稳定业务材料，不通过更换样例制造更好结果。
- 区分自然 bad case、真实依赖失败和确定性契约失败。
- 区分探索实验与验收实验。
- 支撑准入或验收时，预先冻结数据、版本、对照、指标、通过条件和预算。
- 运行后不删除失败样例、不回改阈值、不覆盖旧结果。
- 真实依赖失败可以成为失败记录，不能静默替换为 Mock 成功。

## 代码与文档

- 概念篇通常不改代码。
- 机制篇不因已有代码而转为源码讲解。
- 新观察维度进入已有或必要的新 demo。
- 新通用能力扩展唯一 package。
- 产品组合只进入 `source/apps/review_assistant/`。
- 不为每篇文档创建 package、demo 或 app。
- 不预建空实现、空 fixture 或占位运行入口。

Agent 课程默认以成熟框架为主路径：先直接运行框架，再通过公开运行模型理解机制，最后在出现真实复用和稳定契约时提取本地抽象。最小原生 Loop 只用于观察控制流和责任边界，不逐步长成与框架竞争的教学框架。

`source/packages/agent_core/` 可以封装 LangChain、LangGraph 等框架，但必须形成可说明、可测试、可替换的稳定边界，例如请求结果契约、Tool 治理、通用状态与停止原因、事件与 Trace、框架或协议适配。只转发一次调用的包装层不成立；框架已有的调度器、图执行器、Checkpoint 引擎不得在本地重复实现。领域 Prompt、评审 Schema、引用策略、允许路径与命令、记忆策略和具体角色编排属于产品的 `agent/` 目录。

框架相关内容按职责归位：机制篇解释 Loop、State、Middleware、Checkpoint、Interrupt、事件与错误语义，以及框架承担和应用保留的责任；实验篇固定框架与 SDK 版本，承担安装、完整调用、日志、调试、读码和迁移差异。不能把所有框架知识推迟到实验篇，也不能让机制篇退化为 API 教程或框架源码导览。

README 分工：package README 维护职责和公共 API；demo README 维护入口、测试和实验链接；产品 README 维护安装、配置、运行、API 与排错；课程实验篇维护完整学习操作。

## 完成自检

- [ ] 核心问题单一，学习者输入、本文交付和非目标明确。
- [ ] 解释从具体问题开始，新概念首次出现时已经解释。
- [ ] 学习路径条目有问题与交付，知识地图节点有说明。
- [ ] 没有复制其他真源或记录迁移过程。
- [ ] 概念篇没有被实现或项目任务主导。
- [ ] 机制篇没有命令、安装、完整日志和系统性源码导览。
- [ ] 实验篇能从干净环境运行，并有预测、单变量、日志阅读、排查、读码、修改和验证。
- [ ] 项目篇引用 SPEC，有检查点、需求变更和验收证据。
- [ ] 学习主线与产品准入已经区分。
- [ ] 协议正文已核对官方规范，版本特性、扩展和已弃用内容没有冒充稳定核心。
- [ ] 框架、`agent_core` 与产品 Agent 的责任分层明确，机制与 SDK 用法没有混写。
- [ ] 本地封装来自真实复用和稳定契约，没有重复实现框架运行时或制造机械门面。
- [ ] 真实调用失败不会静默变成 Mock 成功。
- [ ] 删除内容的目标归属已经存在，链接、注释和测试路径有效。

## 禁止

- 建立第二套课程顺序或阶段内版本轴。
- 将知识地图条目机械扩写成正文。
- 让机制篇退化为源码导览。
- 让实验篇退化为命令清单或重复完整原理。
- 让项目篇复制 SPEC 或产品 README。
- 用 Mock 证明真实模型、检索或 Agent 质量。
- 用压缩行数代替职责归位和学习完整性。
- 把所有框架知识推迟到实验篇，或在机制篇逐行讲框架 API 和源码。
- 把 `agent_core` 建成与成熟框架竞争的自研框架，或建成没有稳定契约的转发壳。
- 未经用户要求创建 Git commit 或 tag。
