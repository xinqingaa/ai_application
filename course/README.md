# AI 应用课程

这里是学习者进入课程的首页。

课程只围绕一个项目展开：把“需求评审助手”从固定 RAG 基线逐步演进为可信评审、单 Agent、可控 Workflow 和多 Agent 评审系统。

## 从这里开始

第一次进入课程，直接打开：

> **[需求评审助手标准学习路径](learning-path.md)**

这条路径是阅读顺序的唯一真源。不要按照 `concepts/`、`mechanisms/`、文件名或代码目录自行推断先后。`concepts/` 与 `mechanisms/` 均为平铺正文，不按能力域分子目录。

如果只是查某项知识属于哪里、依赖什么、是否已有正文，使用：

> [AI 应用知识地图](knowledge-map.md)

## 最终要做出什么

需求评审助手接收 PRD、业务规则、接口文档、客户端规则和历史评审资料，输出结构化风险、依据和需要补充的信息。

它按照同一个业务闭环逐步增加能力：

```text
真实模型理解需求
→ 外部资料可以被检索
→ 检索证据进入模型上下文
→ 输出能够被程序校验
→ V0 最小工作台展示结果、来源、状态和失败
→ 证据不足时拒答或追问
→ V1 可信证据界面关联风险与引用
→ 用固定样例评估和回归
→ V2 质量工作台承载评估、bad case 和反馈
→ 单 Agent 动态补检索
→ V3 运行界面展示工具、证据变化和停止原因
→ Workflow 管理状态和人工介入
→ 多 Agent 分工、汇总与冲突处理
→ 可运行、可观察、可部署的产品
```

课程设计从这个目标反推知识，但学习者不是倒着读项目：

```text
设计课程：项目目标 → 反推需要哪些知识
学习课程：项目愿景 → 概念 → 机制与实验 → 项目综合实践
```

## 文档和代码分别负责什么

| 入口 | 学习时用来做什么 |
| --- | --- |
| `course/learning-path.md` | 确定现在读什么、下一步进入哪里 |
| `course/knowledge-map.md` | 查看完整知识范围、前置和落地位置 |
| `course/concepts/` | 建立定义、区别、判断和能力边界 |
| `course/mechanisms/` | 理解数据流、实现、实验和失败定位 |
| `course/project/` | 组合已有能力，完成项目版本和验收 |
| `source/packages/` | 阅读可复用能力的唯一真实实现 |
| `source/demos/` | 运行机制对照和失败复现 |
| `source/apps/` | 观察学习期 API、SSE 等组合实验 |
| `review_assistant/` | 运行和演进最终产品 |

概念篇、机制篇和项目篇是职责分类，不是三个要分别读完的目录。标准学习路径会根据认知前置在它们之间穿插。

## 两个阶段

| 阶段 | 目标 |
| --- | --- |
| 阶段一：V0–V3 | 固定 RAG → 可信结构化评审 → 质量闭环 → 单 Agent RAG |
| 阶段二：V4–V6 | 可控 Workflow → 多 Agent 评审 → 工作台整合、部署与作品化 |

AI Native 前端从 V0 开始随产品版本演进：V0 建立最小评审入口，V1 呈现可信证据，V2 建立质量工作台，V3 呈现 Agent 运行过程。V6 负责整合和完善，不是前端的起点。

每个版本都遵循：

```text
补充必要概念和机制
→ 运行真实实验
→ 进入项目篇组合能力
→ 主动制造失败
→ 修改一个需求
→ 用测试或评估验收
```

## 真实调用

LLM、RAG、Agent 和 Eval 的学习主路径调用真实模型或真实外部服务。缺少 key、限流、超时和能力不支持时应清晰失败，不静默返回 Mock 结果。

fake、mock 或 simulation 只用于单元测试、离线排查、稳定复现失败路径或明确标注的对照实验，不能证明真实模型或项目质量。

`python_base/` 是已经完成的 Python 基础练习，遇到 Python、HTTP、JSON、异步或 FastAPI 基础问题时按需回查，不是进入主线前必须重新通关的课程。
