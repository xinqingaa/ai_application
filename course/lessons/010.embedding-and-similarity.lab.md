# 真实 Embedding 表示与相似度实验

配套机制：[Embedding 表示与向量相似度](010.embedding-and-similarity.mechanism.md)。本实验只观察固定句对怎样进入真实 Embedding 空间并产生相似度或距离，不执行整库检索，也不证明最终召回和生成质量。

## 1. 前置与真实配置

根 `.env` 和模型配置必须提供真实 Embedding 服务。开始前确认：

- `embedding.default` 或准备使用的 `config_ref` 存在。
- Provider、模型、维度和输入限制真实可用。
- 不会在缺少 Key 时改用假向量或本地随机向量。
- 预处理版本固定为本轮实验身份的一部分。

固定探针位于 `source/apps/review_assistant/fixtures/rag/retrieval/embedding_probes.json`，继续使用“售后入口与订单状态”业务域。

## 2. 先运行默认探针

```bash
uv run python source/demos/rag_retrieval_lab/inspect_embedding.py
```

运行前预测：

- “申请售后”与“发起逆向服务”的方向是否比无关内容更接近。
- 精确标识 `source_channel` 是否一定依赖语义相似度。
- “售前入口”和“售后入口”可能为何很近但业务不同。
- 否定规则相似是否代表模型理解了“不允许”。

默认输出应展示 Provider、模型、维度、预处理版本、metric 和各探针比较结果。

## 3. 展开全部成对分数

```bash
uv run python source/demos/rag_retrieval_lab/inspect_embedding.py --verbose
uv run python source/demos/rag_retrieval_lab/inspect_embedding.py --log-format json
```

可用参数：

| 参数 | 作用 |
| --- | --- |
| `--config-ref` | 选择真实 Embedding 配置 |
| `--metric` | 选择当前实现支持的比较方式 |
| `--probes` | 选择需要运行的探针身份 |
| `--preprocessing-version` | 固定或改变预处理空间身份 |
| `--verbose` | 展开全部成对比较 |
| `--log-format json` | 输出结构化事件 |

切换 metric 前先写明“越大越近”还是“越小越近”。不能只看数值大小而忽略度量方向。

## 4. 记录空间身份

一次可比较的 Embedding 记录至少包括：

- Provider 和配置引用。
- 模型名。
- 向量维度。
- 预处理版本。
- metric。
- 输入身份。

模型、维度或预处理变化后，旧向量不应继续与新 Query 向量混用。维度相同也不能证明来自同一语义空间。

## 5. 怎样解读结果

| 结果 | 可以说明 | 不能说明 |
| --- | --- | --- |
| 同义表达更近 | 当前空间捕捉到一定语义接近 | 整库中一定排进 Top-k |
| 相邻业务主题很近 | 空间可能产生业务噪声 | 模型已经理解业务规则 |
| 精确标识分数一般 | 语义路线未突出该标识 | Lexical 路线也找不到 |
| 否定句很近 | 主题接近 | 已理解否定和例外关系 |
| 无关文本分数异常 | 当前空间或探针值得调查 | Provider 一定故障 |

## 6. 失败时按层排查

| 表现 | 可能层次 | 验证方式 |
| --- | --- | --- |
| 缺少 Key 或鉴权失败 | Provider 配置 | 保留真实错误，不生成假向量 |
| 模型不存在 | config_ref 或模型能力 | 核对模型配置和服务支持 |
| 返回维度变化 | 模型或服务配置变化 | 比较空间身份，旧索引需要重建 |
| 输入超限 | 批量或文本长度 | 减少本轮输入，不静默截断后混入同一记录 |
| metric 报错 | 参数契约 | 查看支持的 choices 和测试 |
| 分数方向判断反了 | metric 语义 | 先确认 similarity / distance 定义 |

## 7. 读码顺序

1. `source/demos/rag_retrieval_lab/inspect_embedding.py`：探针、参数和输出怎样组织。
2. `source/packages/rag_core/embedding/`：RAG 侧记录、空间身份和比较。
3. `source/packages/llm_core/client/service.py` 的 Embedding 入口：真实 Provider 怎样调用。
4. 模型配置：Chat 与 Embedding 为什么分开。
5. `source/packages/rag_core/tests/test_embedding.py` 和 `source/packages/llm_core/tests/test_client_embed.py`：确定性契约。

## 8. 单变量修改与验证

选择一种修改：

- 固定模型，只改变一组句对。
- 固定探针，只切换 metric。
- 固定输入和 metric，只切换另一个真实 Embedding 配置，并将其记录为新空间。

不能同时更换模型、预处理、探针和 metric 后比较一个最终分数。

运行：

```bash
uv run pytest source/packages/rag_core/tests/test_embedding.py \
  source/packages/llm_core/tests/test_client_embed.py -q
```

确定性测试证明空间身份、维度、输入和比较契约；真实模型的分数与服务可用性仍以本实验结果为准。
