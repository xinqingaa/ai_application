# Chunk 策略与 Metadata 对照实验

配套机制：[Chunking、父子块与 Metadata](009.chunking-and-metadata.mechanism.md)。本实验复用已经成功解析的同一份 Markdown 文档，只改变 Chunk 策略或预算，观察边界、重叠、父子关系、来源定位和稳定身份。

Chunk 数量更多、文本更长或相关事实位于同一块，都不能单独证明最终检索质量更好。

## 1. 前置

先完成[真实文档解析实验](008.document-loading-and-cleaning.lab.md)，确认 Markdown fixture 能形成稳定 `DocumentElement`。本实验不重新解释格式解析，也不把损坏文件作为主要变量。

## 2. 运行四种策略基线

```bash
uv run python source/demos/rag_ingestion_lab/inspect_chunking.py
```

默认比较：

- `element_baseline`：每个 Element 直接成为检索块的基线。
- `fixed_window`：按容量与 overlap 组织文本。
- `structure_aware`：利用已经恢复的标题和元素结构。
- `parent_child`：区分检索粒度和提供给模型的父级上下文。

运行前预测：

- 哪种策略会产生最多 Chunk。
- “允许申请售后”和“虚拟商品除外”是否位于同一检索块或同一 parent。
- overlap 会增加哪些重复。
- 标题路径和原始 locator 应怎样保留。

## 3. 单独改变窗口预算

```bash
uv run python source/demos/rag_ingestion_lab/inspect_chunking.py \
  --policy fixed \
  --max-tokens 32 \
  --overlap-tokens 6
```

保持文档和策略类型不变，再分别只改变一个参数：

```bash
uv run python source/demos/rag_ingestion_lab/inspect_chunking.py \
  --policy fixed \
  --max-tokens 48 \
  --overlap-tokens 6
```

比较 Chunk 数量、Token 分布、重复量、事实边界和 `chunk_id`。有效切分策略或内容变化时，身份应能区分新旧结果；同一输入和同一策略重复运行应稳定。

## 4. 展开父子块和来源

```bash
uv run python source/demos/rag_ingestion_lab/inspect_chunking.py \
  --policy parent-child \
  --verbose
```

观察：

- child 的 `chunk_id` 和 parent 身份。
- child 用于检索、parent 用于扩展上下文时分别保存什么。
- 每个块覆盖哪些原始 Element 和 locator。
- 标题路径、业务 Metadata 和策略 Metadata 是否混在一起。
- 一个事实跨多个 Chunk 时怎样保留来源跨度。

## 5. 输出怎样读

| 字段 | 要回答的问题 |
| --- | --- |
| policy / token budget | 本轮主要变量是什么 |
| chunk count | 文档被组织成多少检索单位 |
| token distribution | 是否出现极小、极大或不均衡块 |
| duplicate / overlap | 为边界补偿付出了多少重复代价 |
| fact grouping | 相关规则位于同块、同 parent 还是完全分离 |
| chunk_id | 同一策略是否稳定，策略变化是否产生新身份 |
| source spans / locator | 能否回到原始文档位置 |

## 6. 参数错误与自然边界

参数非法应由公共契约立即拒绝，例如 overlap 不小于窗口、预算非正数或未知策略。这些是确定性输入错误。

以下属于正常策略代价，不应伪装成程序错误：

- 小窗口切断相关规则。
- 大窗口引入更多无关文本。
- overlap 增加重复候选。
- 原始文档结构本身不足，structure-aware 也无法恢复不存在的语义层次。
- 父子块改善上下文完整性，但增加存储和装配复杂度。

## 7. 读码顺序

1. `source/demos/rag_ingestion_lab/inspect_chunking.py`：固定文档、构造策略和呈现对照。
2. `source/packages/rag_core/chunking/` 公共入口：Element 怎样进入策略。
3. 各策略实现：只追踪当前正在实验的一种策略。
4. Chunk 模型与身份生成：来源、parent 和策略版本怎样进入契约。
5. `source/packages/rag_core/tests/test_chunking.py`：稳定身份、边界和非法参数。

## 8. 修改与验证

选择一个变量：

- 调整 fixed window 的 `max-tokens`。
- 调整 overlap。
- 调整 parent 容量。
- 在不改变正文事实的情况下增加标题层次。

先写下哪些 Chunk 边界和身份应变化，哪些文档身份、业务 Metadata 和原始 locator 不应变化。然后运行：

```bash
uv run pytest source/packages/rag_core/tests/test_chunking.py -q
```

再运行相同实验命令两次，确认同一输入和策略产生稳定结果。检索收益留到后续 Retriever 实验验证，不在本节下结论。
