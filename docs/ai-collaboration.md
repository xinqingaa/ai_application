# AI 协作指南

本文规定 AI Agent 怎样识别任务、选择真源、执行验证和避免越界。课程写作细节见 [learning-guide.md](learning-guide.md) 与仓库 Course Writing Skill，代码掌握标准见 [ai-coding-mastery.md](ai-coding-mastery.md)。

## 1. 真源顺序

1. 用户当前明确目标。
2. 根 `AGENTS.md`。
3. `SPEC.md`、`PLAN.md` 与 `docs/strategy.md`。
4. `docs/learning-guide.md` 和任务对应的课程、代码 README。
5. `docs/ai-coding-mastery.md` 与远期平台参考。

下层文档可以补充细节，不能悄悄改变上层产品职责、学习顺序或工程边界。发现冲突时先指出冲突和真源，不通过复制一份新规则绕开。

## 2. 任务分类

开始前先判断主要任务：

- 产品规格：决定做什么、输入输出、安全和验收。
- 工程方案：决定怎样在 `source/` 分层实现。
- 课程规划：决定学习顺序、前置、粒度和文档入口。
- 课程写作：编写概念、机制、实验或项目篇。
- 代码实现：修改 package、demo 或产品。
- 诊断审查：只调查原因、风险和证据，不自动实施。
- 迁移重构：移动职责、删除旧内容并保持闭环。

一个请求可能跨越多类任务，但每项修改仍要回到自己的真源。

## 3. 任务路由

| 任务 | 首要真源 | 必须补读 |
| --- | --- | --- |
| 产品范围或行为 | `SPEC.md` | 项目篇、产品代码与测试 |
| 工程结构与实现顺序 | `PLAN.md` | SPEC、相关 package 与 app |
| 学习方式或文档职责 | `docs/learning-guide.md` | Course Writing Skill |
| 课程正文 | Course Writing Skill | 学习路径、知识地图、相邻正文、代码与测试 |
| 阅读顺序 | `course/learning-path.md` | 项目篇和知识地图 |
| 知识完整性 | `course/knowledge-map.md` | 学习路径、SPEC |
| 产品运行 | 产品 README | 锁文件、配置、代码与测试 |
| 代码掌握与审查 | `docs/ai-coding-mastery.md` | 真实入口、日志和测试 |

## 4. 文档任务流程

1. 定位文档类型和唯一真源。
2. 读取相邻课程、配套实验、代码和测试，不能只改当前一页。
3. 说明当前问题、已有输入、本文交付和非目标。
4. 检查新概念是否在第一次出现时解释。
5. 检查正文、实验、项目和 README 是否职责重叠或缺口。
6. 修改后验证编号、链接、引用、术语和前后数据流。

课程精简时不能把“删除”当成“迁移”。必须逐块确认代码、命令、日志、调试、读码和验收内容的新归属，目标位置可用后才删除旧内容。

## 5. 实现任务流程

1. 从 SPEC 找到真实业务问题和验收。
2. 从 PLAN 判断通用能力还是产品取舍。
3. 检查已有 package、demo、app 和测试，避免平行实现。
4. 定义输入、输出、状态、错误、权限、副作用和外部依赖。
5. 先使用满足需求的最简单结构。
6. 实现后运行与风险相称的测试和真实实验。
7. 更新真正受影响的 SPEC、项目篇、README、Schema、fixture 或评估，不做全仓机械同步。

新能力没有真实职责、可运行入口和验证证据时，不预建空 package、空 demo、空 app 或占位配置。

## 6. 验证纪律

验证必须覆盖用户请求的范围，不能用一个窄测试证明整项重构完成。

- 文档修改：检查编号、链接、节点说明、职责归属和前后逻辑。
- 机制迁移：检查实验篇是否真的能准备、运行、观察、定位、修改和验证。
- 代码修改：运行确定性测试，并按需要运行数据库、Provider、协议或产品集成。
- 质量结论：回到固定样例、版本、对照和运行记录。
- 真实依赖不可用：报告真实失败，不切换为 Mock 后宣称通过。

检查脚本、绿色测试和链接扫描只是证据之一。使用它们前先确认覆盖了哪些要求，未覆盖部分继续人工审查。

## 7. 平台和复杂度准入

引入框架、协议或平台能力前回答：

1. 当前产品问题是什么。
2. 普通程序或已有能力为什么不足。
3. 新能力的稳定契约和失败边界是什么。
4. 权限、状态、副作用和运维成本怎样变化。
5. 有什么基线可以比较收益、成本和失败边界。

课程需要学习某项机制，不等于产品必须启用。远期平台能力不能扩大当前 SPEC。

## 8. 执行边界

- 先找到唯一真源，再修改引用处。
- 不把迁移过程、实时进度和临时争论写入长期文档。
- 不为同一能力创建平行 package、demo 或产品。
- 不用 Mock 冒充真实模型、检索或 Agent 结果。
- 不让平台远期能力扩大当前 SPEC。
- 默认不读取或扩展 `archive/`。
- 保留用户已有改动，不用破坏性命令解决冲突。
- 未经用户要求不创建 commit 或 tag。

## 9. 交付

交付时说明：

- 完成了什么，以及对应真源。
- 运行了哪些检查，它们分别证明什么。
- 哪些真实外部依赖没有运行及原因。
- 是否存在尚未实现、条件接入或保留扩展的边界。
- 用户下一步从哪个文件、命令或课程入口继续。
